# External Integrations

**Analysis Date:** 2026-09-29

The project is a self-contained robotics stack. It has no cloud APIs, databases, auth providers, or telemetry. Its "integrations" are hardware buses, ROS 2 topics, Gazebo, a local WebSocket page, and CI/container infrastructure.

## APIs & External Services

**Third-party web/cloud APIs:**

- None detected. No HTTP client libraries, SDKs, or outbound network calls in `ros2_ws/src/` or `tools/`. Runtime container images are pulled from Docker Hub only at build time.

**Simulation:**

- Gazebo Sim (Harmonic on Jazzy, Jetty on Lyrical) - physics, IMU, lidar and ToF sensors.
  - Client: `ros_gz_sim` (`gz_sim.launch.py`, `create`) and `ros_gz_bridge` (`parameter_bridge` with a generated YAML config) in `ros2_ws/src/dog_gazebo/launch/sim.launch.py`.
  - World: `ros2_ws/src/dog_gazebo/worlds/flat.sdf`; terrains generated by `ros2_ws/src/dog_gazebo/dog_gazebo/terrain.py`.
  - Bridges: `ros2_ws/src/dog_gazebo/dog_gazebo/joint_command_bridge.py` (ROS `joint_commands` -> Gazebo joint controllers), `ros2_ws/src/dog_gazebo/dog_gazebo/tof_bridge.py` (Gazebo `LaserScan` cones -> `sensor_msgs/Range` on `tof/<name>`).
  - Isolation: each check uses its own `ROS_DOMAIN_ID` and `GZ_PARTITION` (`ros2_ws/src/dog_gazebo/dog_gazebo/terrain_sweep.py`).

**Hardware buses (Linux I2C, `/dev/i2c-0`):**

- PCA9685 16-channel PWM driver, address 0x40, 50 Hz - drives 12 servos.
  - Access: `ros2_ws/src/dog_hardware/src/servo_bus.cpp` (`Pca9685Bus`, `MockBus`), `ros2_ws/src/dog_hardware/src/servo_driver.cpp`, node `ros2_ws/src/dog_hardware/src/servo_driver_node.cpp`.
  - Config: `ros2_ws/src/dog_bringup/config/servos.yaml` (`backend: pca9685 | mock`, `i2c.device`, `i2c.address`).
  - Probe tool: `ros2_ws/src/dog_hardware/src/pca9685_probe.cpp`.
- MPU6050 IMU, 0x68 / 0x69 - `ros2_ws/src/dog_hardware/src/imu_sensor.cpp`, node `imu_node.cpp`, publishes `/dog/imu/data`. Config `ros2_ws/src/dog_bringup/config/imu.yaml` (`backend: auto | mock | off`).
- INA226 / INA219 current sensor, 0x41 / 0x44 / 0x45 (optional) - `ros2_ws/src/dog_hardware/src/power_sensor.cpp`, node `power_monitor_node.cpp`, publishes `/dog/power`, triggers e-stop or "lie down". Config `ros2_ws/src/dog_bringup/config/power.yaml`. 0x40 is never probed.

**Input devices:**

- Gamepad via Linux joystick API `/dev/input/js0` (Xbox and PlayStation profiles) - `ros2_ws/src/dog_teleop/src/gamepad_node.cpp`, `joy_teleop_node.cpp`, mapping in `ros2_ws/src/dog_teleop/src/mapping.cpp`; button/axis config in `ros2_ws/src/dog_bringup/config/teleop.yaml` and `teleop_ps.yaml`.
- Terminal keyboard - `ros2_ws/src/dog_teleop/src/keyboard_teleop.cpp` (needs a TTY).

**Perception sensors (simulated only; no real-hardware drivers detected):**

- Two crossed LD19-class single-beam lidars, GS2 line lidar, four VL53L1X ToF sensors - configured under `sensors:` in `ros2_ws/src/dog_bringup/config/robot.yaml`; consumed by `ros2_ws/src/dog_perception/src/perception_node.cpp` (topics `/scan`, `gs2/scan`, `tof/<name>`) and `localization_node.cpp`. See `docs/HEAD.md`, `docs/PERCEPTION.md`, `docs/LOCALIZATION.md`.

**Internal ROS 2 interface (namespace `/dog`):**

- Published: `joint_states`, `servo_pulses`, `imu/data`, `power`, `estop`, `odom`, `state`, `perception/*`, `guard`, `terrain/profile`, `localization/pose|status|map`.
- Subscribed/commanded: `cmd_vel`, `command`, `joint_commands`, `localization/command`.
- Definitions: `ros2_ws/src/dog_hardware/src/*_node.cpp`, `ros2_ws/src/dog_perception/src/*_node.cpp`, `ros2_ws/src/dog_web/dog_web/web_teleop.py`.

**Web teleop / calibration channel (served by the robot):**

- HTTP + WebSocket on `0.0.0.0:8080`, endpoint `/ws`, JSON text messages (`ros2_ws/src/dog_web/dog_web/wsserver.py`, `protocol.py`, `web_teleop.py`, `calibration.py`; static page in `ros2_ws/src/dog_web/static/`).
  - Client for laptops: `tools/autocal/robotdog_autocal/client.py` (stdlib socket-based WebSocket client; no ROS needed on the laptop).
  - No authentication or TLS on this endpoint (see below).
- Local config form: `tools/robot_setup/robot_setup.py` serves `http://localhost:8765` (stdlib `http.server`) and rewrites `ros2_ws/src/dog_bringup/config/robot.yaml` / `servos.yaml`, keeping `*.bak` (gitignored).

## Data Storage

**Databases:**

- None.

**File Storage:**

- Local filesystem only.
  - Robot/servo calibration: YAML in `ros2_ws/src/dog_bringup/config/` (bind-mounted read-only into the container by `docker-compose.yml`).
  - Localization map: written to a path passed as `map:=` to `sim.launch.py` (e.g. `room_map`); traces and results as JSON (`terrain_sweep --out`, `localization_check --trace`).
  - Report data: `tools/sim_video/report/data/*.json`; videos in `report/videos/*.mp4` and posters in `report/posters/*.jpg` (committed).

**Caching:**

- None.

## Authentication & Identity

**Auth Provider:**

- None. Custom safety gating instead of identity:
  - Deadman button on every teleop source; command timeout (0.4-0.5 s) in `ros2_ws/src/dog_bringup/config/teleop.yaml` and `servos.yaml` (`command_timeout`).
  - E-STOP on `/dog/estop` from any pad, plus over-current / under-voltage handling in `ros2_ws/src/dog_hardware/src/power_monitor_node.cpp`.
- The web teleop port has no login: anyone on the network segment can drive the robot. ROS 2 DDS is also unauthenticated (`ROS_DOMAIN_ID=0`, host networking).

## Monitoring & Observability

**Error Tracking:**

- None.

**Logs:**

- ROS 2 logging (`RCLCPP_*`, `get_logger()`), console output; `docker compose logs -f`. Gazebo verbose `-v 2`. CI captures `sim.log`, `perc_*.log`, `loc_*.log` as artifacts.
- Live telemetry: `perception/stats`, `servo_pulses`, `power`, shown on the web page.

## CI/CD & Deployment

**Hosting:**

- Robot: Banana Pi via `docker compose up -d --build` (on-device build; `restart: unless-stopped`).
- Sim: local `docker build -f docker/Dockerfile.sim`. No registry publishing (`push: false` in CI).

**CI Pipeline:**

- GitHub Actions, `.github/workflows/ci.yml`, on push to main/master, PRs, manual dispatch. Jobs:
  - `build-test` - `ros:{jazzy,lyrical}-ros-base`, `colcon build/test --packages-skip dog_gazebo`.
  - `autocal` - Python 3.12, `pip install numpy opencv-contrib-python-headless pytest`, `pytest`, `python -m robotdog_autocal demo`.
  - `robot-setup` - `pyyaml pytest`, `robot_setup.py --check`.
  - `simulation` - `osrf/ros:{jazzy,lyrical}-simulation`, headless Gazebo `walk_check`.
  - `terrain` - Jazzy simulation: slope/waves/rough sweeps, perception, hazard guard, greeting, survey, localization checks.
  - `robot-image` - arm64 Docker build via QEMU/buildx (non-PR only).
- Actions used: `actions/checkout@v4`, `actions/setup-python@v5`, `actions/upload-artifact@v4`, `docker/setup-qemu-action@v3`, `docker/setup-buildx-action@v3`, `docker/build-push-action@v6`.
- Legacy workflows under `legacy/v1/.github/` are inert.

**Base images:** `ros:<distro>-ros-base`, `osrf/ros:<distro>-simulation` (Docker Hub).

## Environment Configuration

**Required env vars:**

- `ROS_DISTRO` (set in image), `ROS_DOMAIN_ID` (compose sets 0). Optional: `GZ_PARTITION`, `BUILD_JOBS` (build arg).
- No API keys, tokens, or credentials are required anywhere.

**Secrets location:**

- Not applicable. No `.env*` files detected. `test_servo_config_reader.sh` at the repo root contains a hard-coded private-LAN address and user name in its usage comment (untracked; remove before committing).

## Webhooks & Callbacks

**Incoming:**

- None (the only inbound endpoint is the web teleop WebSocket on :8080 described above).

**Outgoing:**

- None.
