## Directory Purposes

**`ros2_ws/src/dog_control/`:**

- Purpose: Locomotion control: state machine, gait engines, kinematics
- Contains: C++ header files (include/dog_control/*.hpp), implementation (src/*.cpp), tests (test/*.cpp)
- Key files: 
  - `locomotion.hpp` — State machine modes and LocomotionController class
  - `gait.hpp` — Trot gait (periodic foot motion)
  - `crawl.hpp` — Crawl gait (terrain-adaptive, three feet down)
  - `kinematics.hpp` — Forward/inverse kinematics for 3-dof leg
  - `locomotion_node.cpp` — ROS 2 node wrapper, 50 Hz control loop

**`ros2_ws/src/dog_hardware/`:**

- Purpose: Hardware drivers for servos, IMU, power monitor
- Contains: C++ servo/sensor abstractions and ROS node wrappers
- Key files:
  - `servo_driver.hpp` — PCA9685 I2C protocol, angle→pulse, calibration
  - `servo_bus.hpp` — Mock/real I2C bus abstraction
  - `servo_driver_node.cpp` — ROS node, writes joint_commands to servos
  - `imu_sensor.hpp` — MPU6050 quaternion orientation
  - `imu_node.cpp` — IMU publisher (sensor_msgs/Imu)
  - `power_sensor.hpp` — INA226/INA219 current/voltage measurement
  - `power_monitor_node.cpp` — Battery state publisher

**`ros2_ws/src/dog_teleop/`:**

- Purpose: Multiple control interfaces (gamepad, keyboard, joy bridge)
- Contains: C++ input handlers and ROS publishers
- Key files:
  - `gamepad_node.cpp` — Linux /dev/input/js* reader, joy_msgs publisher
  - `joy_teleop_node.cpp` — joy_msgs → cmd_vel/command converter (button mapping)
  - `keyboard_teleop.cpp` — Terminal stdin → cmd_vel (requires TTY)
  - `mapping.hpp` — Button/axis layout for Xbox/PlayStation

**`ros2_ws/src/dog_web/`:**

- Purpose: HTTP + WebSocket web remote control
- Contains: Python asyncio server, static HTML/JS/CSS
- Key files:
  - `web_teleop.py` — ROS 2 node, HTTP server, WebSocket handler
  - `wsserver.py` — WebSocket protocol (separate from ROS)
  - `protocol.py` — JSON message parsing, velocity/command serialization
  - `calibration.py` — Servo calibration UI bridge
  - `static/` — HTML page, JavaScript (virtual joystick, gamepad API, keyboard)

**`ros2_ws/src/dog_description/`:**

- Purpose: URDF generation from robot.yaml (no xacro)
- Contains: Python YAML parser, URDF builder
- Key files:
  - `urdf.py` — `load_config()`, `build_urdf()`, physics/inertia helper functions
  - `test/test_urdf.py` — Validates URDF against kinematics

**`ros2_ws/src/dog_bringup/`:**

- Purpose: Launch orchestration, shared configuration, utilities
- Contains: 
  - `launch/robot.launch.py` — Main entry point; conditional node startup
  - `config/` — YAML: robot.yaml (geometry), servos.yaml (calibration), teleop*.yaml, power.yaml, imu.yaml
  - `scripts/` — Utilities (calib_pose, etc.)
  - `test/test_mock_bringup.py` — Integration test: full stack with mock hardware

**`ros2_ws/src/dog_perception/`:**

- Purpose: Terrain analysis and localization (optional nodes)
- Contains: C++ nodes and Python reference implementation
- Key files:
  - `perception_node.cpp` — Lidar/ToF → ground plane, elevation map, obstacles
  - `localization_node.cpp` — SLAM-like map building and pose tracking
  - `dog_perception/core.py` — ROS-independent geometry (numpy, offline analysis)
  - `src/submaps.cpp`, `src/core.cpp`, `src/localization.cpp` — Core algorithms

**`ros2_ws/src/dog_gazebo/`:**

- Purpose: Simulation, automated tests, scenario validation
- Contains: Python launch/test scripts, Gazebo world files
- Key files:
  - `launch/sim.launch.py` — Start Gazebo, load world, spawn robot, connect to ROS
  - `worlds/` — .world files (flat, slope, terrain, stairs)
  - `dog_gazebo/walk_check.py` — Test harness: 8-direction walk validation
  - `dog_gazebo/terrain_sweep.py` — Systematic slope/height scanning

## Naming Conventions

**Files:**

- ROS 2 nodes: `*_node.cpp` (e.g., `locomotion_node.cpp`, `servo_driver_node.cpp`)
- Libraries (non-ROS): `*.hpp` headers + `*.cpp` implementation (e.g., `kinematics.hpp`)
- Python modules: lowercase with underscores (e.g., `web_teleop.py`, `wsserver.py`)
- Launch files: `*.launch.py` (e.g., `robot.launch.py`)
- Config files: snake_case `.yaml` (e.g., `robot.yaml`, `servos.yaml`)
- Tests: `test_*.py` or `test_*.cpp` (e.g., `test_locomotion.cpp`)

**Directories:**

- ROS 2 packages: lowercase, underscores (e.g., `dog_control`, `dog_hardware`)
- Include directories: `include/<package>/` (e.g., `include/dog_control/`)
- Source: `src/` for `.cpp` files, `<package>/` for `.py` modules (Python convention)
- Tests: `test/` subdirectory
- Configs: `config/` subdirectory (typically in bringup package)

**Code symbols (C++):**

- Classes: PascalCase (e.g., `LocomotionController`, `ServoDriver`, `SensorMount`)
- Functions: camelCase (e.g., `setVelocity()`, `loadParams()`)
- Constants: UPPER_CASE (e.g., `kJointNames`, `kMaxVelocity`)
- Enums: PascalCase members (e.g., `Mode::WALK`)

**Code symbols (Python):**

- Classes: PascalCase (e.g., `WebTeleop`, `Server`)
- Functions/methods: snake_case (e.g., `load_config()`, `mounts_from_params()`)
- Module constants: UPPER_CASE (e.g., `LEGS`, `DEFAULT_DESCRIPTION`)

## Where to Add New Code

**New Feature (e.g., dynamic obstacle avoidance in trot):**

- Primary code: `ros2_ws/src/dog_control/src/locomotion.cpp` (or new `avoidance.hpp` library)
- Tests: `ros2_ws/src/dog_control/test/test_avoidance.cpp` (unit) + `ros2_ws/src/dog_gazebo/dog_gazebo/obstacle_check.py` (integration)
- Config: Add parameters to `ros2_ws/src/dog_bringup/config/robot.yaml` (gains, thresholds)

**New Control Input Method (e.g., voice commands):**

- Implementation: New package `ros2_ws/src/dog_voice_teleop/` (or within `dog_teleop/`)
- Input handler: `src/voice_node.cpp` (subscribes to speech topics, publishes cmd_vel/command)
- Tests: `test/test_voice.cpp` or `.py`

**New Sensor (e.g., additional lidar):**

- Driver node: `ros2_ws/src/dog_hardware/src/lidar_node.cpp` (or new package)
- Integration: Add launch line in `robot.launch.py` with `lidar` argument
- Config: Parameters in `robot.yaml` (mount position, calibration)
- Perception: Integrate scans in `dog_perception/src/perception_node.cpp`

**New Utility Tool (e.g., log replay):**

- Location: `tools/log_replay/` (standalone directory with own setup.py or CMakeLists.txt)
- Entry: Python script or compiled binary
- Documentation: README in tool directory

**Web Interface Enhancement (e.g., new dashboard widget):**

- Frontend: `ros2_ws/src/dog_web/static/index.html` (or separate .html file)
- JavaScript: `ros2_ws/src/dog_web/static/js/` (organized by feature)
- Backend: `ros2_ws/src/dog_web/dog_web/web_teleop.py` (add subscription/endpoint if needed)
