## Accomplishments

- `RampParams`/`Ramp`: hard limits `kMaxAmpDeg = 30.0`, centre 1000..1800 us, speed grid 1.5..10.0 rad/s (`kDefaultSpeedsRadS`, ascending, at most 32 entries), `hold_s` 0.4..10 s, `rest_s` 0.3..60 s; `validate()`/`validateSpeeds()` return the field name instead of throwing. The generator emits APPROACH (hold at the centre, then a ramp to A) straight into stroke 0, 150 strokes numbered 0..149 with 0.4 s holds and 3 s rests between groups (14 of them); `cmd_us` is a pure function of the in-phase time and is clamped to [A, B] with a 1e-9 margin; `plausibility_window` is true exactly on strokes 0 and 1.
- `Ramp::update` carries the leftover `dt` across a phase boundary, so the total time is tick-size independent: measured equal to `plannedDurationS()` (136.194 s on the defaults) to within one tick at dt 0.001 and dt 0.0071. The tracer test drives `FakePwm` at 50 Hz through a 3.0 rad/s run: first pulse exactly at the centre, last at A, maximum B, all writes true, one `release()`.
- `SafetyGuard`: no current filter (a spike would be hidden); each reading updates the whole state, then one event is chosen by priority `SATURATION > OVERCURRENT > PCA_ERROR > INA_ERRORS > TICK_OVERRUN > IMPLAUSIBLE_SHUNT > TIMEOUT` and returned once. Sustained 2.5 A trips at exactly 0.150 s (49 ms does not; negative current the same); saturation fires on a single 30500 sample (30300 does not; 7700/7500 on 10 mOhm); the plausibility peak is judged on the first call after the window falls (0.01/0.02 A too low, 3.01 A spike too high, 0.5 A passes, an error-only window peaks at 0); 3 consecutive INA errors trip (an error between over-threshold samples does not clear the 50 ms window; raw of a failed read is ignored); `pca_ok == false` trips at once; 60 ms between updates is a tick overrun; `max_seconds` 2.0 times out at 2.000 s. A broken configuration makes `ok()` false and lets go with `INA_ERRORS` on the first update.
- `Pca9685Out`: preflight only reads — MODE1 must be awake with auto-increment, PRE_SCALE exactly 121, and every foreign channel's `LEDn_OFF_H` must have the full-off bit; a missing chip, a failed read, sleep, a missing auto-increment or prescale 30/122 all refuse without a single write, with `pca9685_probe check` / `docker compose stop` hints. `setPulseUs` writes one 5-byte transaction to the servo's own registers (`{0x06 + 4*channel, 0, 0, ticks & 0xFF, ticks >> 8}`); `release()` retries 3 times and the destructor always calls it on an armed object (scope exit, exception, or after a refused pulse); MODE1 and PRE_SCALE are never written.
- `pca` constants for plan 01-12: `kAllLedOffBytes = {0xFA, 0, 0, 0, 0x10}` (the same buffer the signal handler will `write()`), `kPrescale50Hz = 121`, `kReleaseAttempts = 3`, `ticksFor` (averaged period 19988.5 us, 50.029 Hz).
- All five suites pass under `tools/local_gtest/run.sh` (6 + 5 + 6 + 9 + 6) and every `src/*.cpp` links into one executable with `-Wall -Wextra -Wpedantic -Werror`.

## Decisions Made

- The ramp's total time must not depend on the tick size, so `cmd_us` is computed from the in-phase time with the leftover `dt` carried across boundaries; the six tests assert this at two tick sizes.
- The plausibility window is exactly the first pair of strokes (ids 0 and 1), as the plan specifies [ASSUMED thresholds 0.03..3 A].
- `DONE` clears `stroke_id` to -1, keeps the last command (A) and the ramp does not drop the outputs — releasing is the session's job (plan 01-12).
- `Pca9685Out` refuses structurally (channel/limits) before touching the bus, and a refused or never-armed object writes nothing at all; only an armed one releases.
- Fail closed: a guard with an invalid configuration trips `INA_ERRORS` on its first update.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `FakeI2cBus::writeBytes` shifted the data bytes one register up**
- **Found during:** Task 3 (the red -> green cycle of `test_pwm_out.cpp`; `PulseEncodingAndLimits` and `DestructorReleasesAllChannels` exposed it)
- **Issue:** the fake stored `data[i]` at register `first + i` for i = 1.., so `data[1]` landed one register past the addressed one, unlike the real wire (and `LinuxI2cBus`, which sends the same buffer to the chip). The plan's own expectations — channel 1 registers 0x0A..0x0D = {0, 0, 0x19, 0x01} and the release frame writing 0xFA..0xFC = 0, 0xFD = 0x10 — could not hold with that shift; a release would have touched PRE_SCALE (0xFE) in the model. No existing test exercised `writeBytes` (grep: only the new `pwm_out.cpp`), so nothing else depended on the shift.
- **Fix:** `dev->regs[first + (i - 1)] = data[i]` and the pointer ends on the last written register; the header comment now states "data[1..] fill it and the registers after it (as on the wire)".
- **Files modified:** `ros2_ws/src/dog_bench/src/i2c_bus.cpp`, `ros2_ws/src/dog_bench/include/dog_bench/i2c_bus.hpp`
- **Verification:** all five suites pass again (6 + 5 + 6 + 9 + 6); the six PwmOut tests now observe the plan's exact register values, and the package links with `-Werror`.
- **Committed in:** 839513c (part of the Task 3 commit); recorded in `.planning/WINDOWS.md` as entry 3 (fixed)
- **Note:** the plan's `files_modified` did not list these two files; the fix was required for the plan's own acceptance criteria, is minimal, and stays inside the `dog_bench` package.
