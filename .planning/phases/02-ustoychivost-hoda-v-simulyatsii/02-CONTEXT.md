# Phase 2 — CONTEXT (решения, обязательные к исполнению)

Фаза 02 «Устойчивость хода в симуляции». Требования: GAIT-03, GAIT-04, GAIT-05.
Все симуляции — только в GitHub Actions (D-08 ниже, продолжение D-24 фазы 1).

## Что должно быть верно по итогу фазы

1. **GAIT-03.** Спуск задним ходом по уклону 7–10° проходит без падения, наклон корпуса остаётся
   в воротах `walk_check` (< 20°).
2. **GAIT-04.** При наклоне выше мягкого порога контроллер сам снижает скорость, а на жёстком —
   прекращает шаг, не дожидаясь аварийного порога. Распределение наклона по плоскому полу и по
   уклонам записано: из него в фазе 4 берутся пороги.
3. **GAIT-05.** `walk_check` с возмущениями (масса ±20 %, трение, задержка 30–50 мс, скорость серв
   3.5–4.0 рад/с) проходит 8/8 хотя бы в пессимистичном углу.

## Решения

- **D-01. Мягкий порог наклона — 15° / 20°** (владелец, 2026-10-27). От 15° до 20° контроллер
  линейно снижает скорость хода: на 15° — полная, на 20° — ноль. На 20° и выше шаг прекращается
  (робот стоит), а не продолжается «медленно». Аварийные пороги не меняются: наклон корпуса к
  поверхности 20° в `walk_check` и падение 60° остаются воротами приёмки.
- **D-02. Зачёт по возмущениям** (владелец, 2026-10-27): каждый параметр проверяется отдельно
  (8/8), затем все худшие значения собираются в один прогон как контрольный. Зачёт — по набору
  «каждый отдельно + комбинация», а не по одному удачному углу.
- **D-03. Пессимистичное трение пола — `mu = 0.6`** (владелец, 2026-10-27): пыльная плитка,
  лёгкое скольжение. Сейчас трение пола задано константой `mu = 1.0` в `terrain.py`.
- **D-04. Масса — груз на корпусе ±20 % от общей массы** (владелец, 2026-10-27), то есть
  ±0.296 кг при текущих 1.48 кг (корпус 0.80 + 4 ноги по 0.17). Масштабирование масс всех звеньев
  не применяется: грузят реального робота, а не меняют его конструкцию.
- **D-05. Возмущения вводятся только входами запуска и приёмки**, без правки трёх согласованных
  чисел скорости серв (`description.servo_velocity`, `servo.max_speed`, `servos.yaml` — их стережёт
  тест контракта из 01-15). В `sim.launch.py` уже есть `servo_speed` и `servo_delay_ms`; для
  трения и груза добавляются такие же входы.
- **D-06. Задержка команд** — существующий `servo_delay_ms`, края 30 и 50 мс (коридор GAIT-05).
- **D-07. Скорость серв** — существующий `servo_speed`, края 3.5 и 4.0 рад/с.
- **D-08. Замеры только в CI** (`tools/ci_dispatch/ci_dispatch.sh`), локальный Gazebo не
  запускается; данные и отчёты — в `.planning/phases/02-*/`.
- **D-09. Порог наклона не трогает аварийную защиту.** `slope_max_deg` (предел компенсации уклона)
  остаётся как есть; новый мягкий порог — отдельный контур ограничения скорости.
- **D-10. Распределение наклона** пишется по ячейкам (плоский пол, уклон 7°, уклон 10°) в отчёт
  фазы; пороги фазы 4 берутся из него, а не назначаются «на глаз».
- **D-11. Критерии зачёта фазы не меняются** правками кода: если замер не проходит, план
  останавливается на `CHECKPOINT REACHED` с числами.

## Что уже есть (проверено по коду 2026-10-27)

- `sim.launch.py`: входы `servo_model` (ideal|real), `servo_speed`, `servo_delay_ms`, `terrain`,
  `level`, `seed`, `heading_hold`, `slope_compensation`, `heading_debug`.
- `servo_sim` в `robot.yaml`: люфт 1.5°, задержка 40 мс, трение шарнира 0.06 Н·м, напряжение шины.
  Задержку и трение шарнира менять не нужно — нужны только края диапазона через входы.
- `terrain.py`: `SURFACE` — константа `mu = 1.0`; миры `flat`, `slope`, `waves`, `rough`, `steps`.
- `terrain_sweep.py`: `--terrain`, `--levels`, `--min-ratio`, `--backward-ratio`, `--domain`;
  на уклоне план манёвров включает спуск задним ходом.
- `urdf.py`: `DEFAULT_DESCRIPTION` с `body_mass: 0.80`; идеальная модель закреплена пином
  `GOLDEN_SHA256`, поэтому вход груза обязан при нуле давать ту же строку URDF.
- `locomotion.cpp`: `setGuardVx()` уже ограничивает скорость вперёд по препятствию (`guard_vx_`),
  есть оценка уклона пола `slope_pitch_`/`slope_roll_` из `setImuAttitude`.

## Чего нет

- Параметра трения пола (мир всегда `mu = 1.0`).
- Груза на корпусе (масса корпуса фиксирована в описании).
- Мягкого порога наклона в контроллере.
- Записи распределения наклона по ячейкам.
