# 02-05: облегчённый корпус — перебор ручек похода

```text
code_sha: eaa6d52 (входы похода), данные на нём же
run_light_duty75: 40543242153 (груз −0.296, duty 0.75, flat_A_bwd10)
run_std_duty75: 40544595360 (без груза, duty 0.75, все ячейки)
run_worst_duty75: 40548043757 (комбинация худших, duty 0.75)
run_worst_duty70: 40549306783 (комбинация худших, duty 0.70)
```

Причина (из `02-ACCEPTANCE-REPORT.md`): облегчённый корпус раскачивается сильнее (размах тангажа
14.3° против 9.3°), контакт прерывается, шаг уходит в проскальзывание. Перебирались ручки шага,
умолчания `robot.yaml` не менялись — всё через входы запуска.

## Комбинация худших (трение 0.6 + груз −0.296 + задержка 50 мс + сервы 3.5)

| `duty` | Jazzy real min / yaw | Jazzy ideal min / yaw | вердикт |
|---|---|---|---|
| 0.65 | 40.3 / 8.8° | 27.4 / 8.3° | real PASS, ideal FAIL по дистанции |
| **0.70** | **42.5 / 8.1°** | 58.4 / **12.8°** | real PASS, ideal FAIL по уводу |
| 0.75 | 50.8 / **12.3°** | 58.5 / **15.5°** | обе модели FAIL по уводу |

Три настройки дают три разных провала, и это не шум: с ростом доли опоры растёт дистанция и
падает устойчивость курса (на четырёх опорах ноги «тянут» друг друга сильнее). `duty 0.70` —
единственная настройка, где гейтуемый элемент (Jazzy real) проходит **оба** критерия с запасом
(42.5 % при воротах 40 %, увод 8.1° при 10°), а идеальная модель упирается только в увод.

## Что предлагается

1. Принять `gait.duty = 0.70` как новое умолчание: оно улучшает все ячейки на штатном роботе и
   убирает провал лёгкого корпуса по дистанции, оставляя запас по обоим критериям на гейтуемом
   элементе.
2. Перед сменой умолчания — прогнать штатного робота по всем ячейкам на `duty 0.70` (сейчас
   проверен 0.75), чтобы не менять настройку по одному углу.
3. Остаточный провал идеальной модели по уводу (12.8°) не лечится долей опоры: это удержание курса.
   Либо отдельная задача на `heading`-контур в этом углу, либо записать как известное ограничение
   идеальной модели с согласия владельца.

Решение по пунктам 1–2 — за владельцем.


## Второй заход: подъём стопы, и почему доля опоры не годится

Первая попытка — поднять `gait.duty`. В симуляторе она работает, но `duty 0.70` на штатном периоде
0.55 с **выводит суставы за паспорт серв**: тест `Locomotion.JointSpeedsFitTheServos` показывает
6.04 рад/с против 5.5 рад/с (6.0 рад/с × 0.8), автопериод честно растягивается с 0.60 до 0.70 с.
То есть выигрыш в симуляторе частично получен насыщением приводов — это не правка, а обход паспорта.
Законная пара «доля 0.70 + период 0.65 с» контракт проходит (время переноса остаётся 0.1925 с), но
это смена двух умолчаний сразу: темп падает на 18 %, `max_step` режет скорость с 0.171 до 0.132 м/с,
а вся база фазы 1 (0.55 с / 0.65) перестаёт быть сравнимой. Отложено.

Работающий вариант — **опустить подъём стопы с 20 до 15 мм**: меньше раскачка и меньше нагрузка на
сервы (автопериод при 6.0 рад/с сокращается с 0.60 до 0.55 с, то есть запас только растёт).

| Угол | `step_height` | Jazzy real min / med | Jazzy ideal min / med | увод (real) |
|---|---|---|---|---|
| груз −0.296 | 0.02 (штат) | 39.8 / 54.9 | 25.9 / 40.4 | 7.6° |
| груз −0.296 | **0.015** | **45.7 / 47.5** | **54.1 / 67.7** | 5.1° |
| комбинация худших | 0.02 | 40.3 / 46.1 | 27.4 / 35.5 | 8.8° |
| комбинация худших | **0.015** | **48.6 / 54.0** | 33.7 / 62.8 | 9.0° |

Штатный робот на 15 мм держится в пределах базы по всем ячейкам (Jazzy real, медианы: плоскость A
57.1 против 59.3, плоскость B 53.2 против 53.9, bwd05 43.4 против 34.0, волны 45.7 против 51.9,
камни 55.8 против 52.5), падений нет.

## Что принято

`gait.step_height` 0.02 → **0.015** как новое умолчание (робот и C++-умолчание), таблица автопериода
в `test_locomotion.cpp` пересчитана тем же кодом (0.875 / 0.7625 / 0.61 / 0.55 вместо 1.03 / 0.905 /
0.72 / 0.60), в `docs/SIMULATION.md` добавлена оговорка, что таблица минимальных периодов посчитана
для шага 20 мм.

Остаточное: идеальная модель в комбинации худших даёт 33.7 % (два повтора из пяти) при уводе 14° —
это уже не про трение, а про удержание курса без динамики серв; записано как известное ограничение
идеальной модели.


## Итог второго захода: одной ручкой оба конца не закрываются

15 мм починили лёгкий конец и комбинацию худших, но **сломали тяжёлый**: при `payload +0.296` Jazzy
real дал 33.1 % (один повтор из пяти 0.33) против 59.2 % на штатных 20 мм. То есть подъём стопы
переставляет провал с одного конца на другой: лёгкому корпусу нужно ниже (меньше раскачка и
проскальзывание), тяжёлому — выше (пронос стопы над полом).

Третий вариант — доля опоры 0.70 с периодом 0.65 с при штатных 20 мм (единственная пара, проходящая
паспорт серв): на тяжёлом конце 51.9 % по дистанции, но увод 10.8° при воротах 10°, то есть снова
на грани. Цена — темп медленнее на 18 %.

| Конфигурация | тяжёлый конец (Jz real) | лёгкий конец (Jz real) | паспорт серв |
|---|---|---|---|
| 0.65 / 0.55 с / 20 мм (штат) | **59.2 %** ✓ | 39.8 % ✗ | ✓ |
| 15 мм | 33.1 % ✗ | **45.7 %** ✓ | ✓ |
| 0.70 / 0.55 с / 20 мм | — | 60.3 % ✓ | **✗ 6.04 рад/с** |
| 0.70 / 0.65 с / 20 мм | 51.9 %, увод 10.8° ✗ | — | ✓ |
| 0.75 / 0.55 с / 20 мм | — | 60.3 % ✓ | ✗ (ещё хуже) |

Вывод: в текущей походке ±20 % массы корпуса — окрестность развилки. Любая **постоянная** настройка
шага двигает провал с одного конца на другой, а не убирает его. Все провалы при этом двугорбые
(один-два повтора из пяти), то есть запас там нулевой, а не отрицательный.

Что из этого следует для GAIT-05 (решение владельца):

1. **Походка, зависящая от нагрузки** — подъём стопы и длина шага по измеренной массе корпуса
   (робот её знает: `body_mass` в конфиге, в симуляции — `payload_mass`). Это единственный путь,
   который закрывает оба конца, но это новая функция, а не настройка.
2. **Сузить полосу масс** (±10 % вместо ±20 %) — тогда штатная настройка держит оба конца.
3. **Оставить как есть** и записать ±20 % как известное ограничение походки фазы 2.

Умолчание `robot.yaml` возвращено к 20 мм: конфигурация, которая ломает тяжёлый конец, не может быть
поставлена по умолчанию. Данные обоих заходов лежат в `acceptance/light-body/`.
