# 03-02: честный E-STOP и надзорная авария — сводка

Код `7a47534` (плюс правки сборки `e90b2a8`, `bc6a9c1`, `f26aacd`). CI `40582393580`:
`build + test (jazzy)` success, `build + test (lyrical)` success — включая новый сквозной
launch-тест.

## Что сделано

1. **Подтверждённое отпускание выходов.** `relax()` возвращает, подтвердила ли шина: `disableAll()`,
   при отказе — один повтор, при повторном отказе — поканальное отключение всех 16 каналов.
   Появились `outputsConfirmedOff()`, `relaxFailures()`, `estopDone()`: пока выходы не подтверждены,
   E-STOP не считается выполненным.
2. **Драйвер объявляет свою аварию.** Защёлка публикует `estop=true` в тот же топик, который слушает
   управление (`locomotion` уходит в `passive`), и пишет причину в лог. Снять защёлку может только
   сервис `~/release_fault` (`std_srvs/Trigger`); `estop=false` в топике защёлку не снимает, иначе
   устаревший пульт молча вооружил бы робота.
3. **Сквозной тест в CI** (`test/test_servo_driver_fault.py`): команды идут плавным движением сустава,
   через секунду все записи на моке начинают отказывать (`mock.fail_after`), драйвер защёлкивает
   аварию и публикует `estop=true`, сервис отвечает `fault released…` и объявление снимается.
4. **Документация**: раздел «Надзорная авария драйвера» в `docs/CONTROL.md` и строка в таблице
   цепочки безопасности; порядок выхода — причина → `release_fault` → `stand`.

## Чего это стоило: сборка

`std_srvs` в проекте не было ни разу, а его нет ни в `ros-base`, ни в simulation-образах. Пришлось
тронуть три места, иначе сборка падала:

- `docker/Dockerfile` — `ros-$DISTRO-std-srvs` в образ;
- `.github/workflows/ci.yml` — установка пакета в четырёх джобах, которые собирают рабочее
  пространство (build + test, gazebo, terrain, acceptance), **после** `actions/checkout` (до него
  контейнер не может зайти в `ros2_ws`, и GitHub показывает это как exit 127);
- `ros2_ws/src/dog_hardware/CMakeLists.txt` — `find_package(std_srvs)` и `${std_srvs_TARGETS}`;
  одного `<depend>` в `package.xml` не хватает, путь к заголовкам берётся из `find_package`.

## Грабли теста

- **Постоянная цель не пишет в шину.** Первый вариант теста держал сустав в одной позе: драйвер
  записывал импульс один раз при включении и дальше молчал, поэтому мёртвая шина не проявлялась.
  Тест водит сустав синусом 0.5 Гц.
- **Клиент сервиса не виден графу сразу.** `wait_for_service` без спина после `create_client` просто
  истекает. Теперь тест берёт список сервисов из графа, ищет `*/release_fault` и падает с полным
  перечнем, если такого нет — так причина видна за один прогон.

## Тесты

- `dog_hardware servo_driver` — **32** (было 28): повтор `disableAll`, поканальный отстой при
  двойном отказе, неподтверждённое отпускание, E-STOP не выполнен без подтверждения.
- Launch-тест `test_servo_driver_fault.py` — 1 тест, зелёный в CI на jazzy и lyrical.
