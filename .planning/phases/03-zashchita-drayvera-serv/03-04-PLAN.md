# 03-04: разоружённый старт и гашение выходов при аварийном выходе (SAF-12, SAF-16)

Сегодня `setTargets()` включает ногу сразу по приходу первой команды, а `Pca9685Bus::open()`
намеренно **не трогает** выходы, если чип уже разогнан на нужную частоту («рестарт драйвера не
дёргает сервы», `servo_bus.cpp:74`). Вторая половина SAF-12 просит обратного — см. вопрос 1
контекста; решено владельцем 2026-10-28 (D-06): выходы гасятся на старте всегда.

## Задача 3: сторож на хосте гасит выходы при аварийном выходе

<task type="auto">
  <files>
    tools/servo_guard/servo-guard.sh,
    tools/servo_guard/servo-guard.service,
    docker-compose.yml
  </files>
  <action>
    Скрипт `tools/servo_guard/servo-guard.sh`: раз в секунду проверяет, жив ли контейнер `robot`; если контейнер
    пропал (или `docker inspect` показывает `exited` с ненулевым кодом) — выполняет
    `docker compose run --rm robot ros2 run dog_hardware pca9685_probe off` и пишет строку в
    journal. Защита от повторного запуска: не чаще одного гашения за 5 с.

    `tools/servo_guard/servo-guard.service` — systemd-юнит на Pi (`Restart=always`, `After=docker.service`).
    В `docker-compose.yml` у сервиса `robot` — `stop_grace_period: 5s`, чтобы `SIGTERM` успевал
    отработать (`relax_on_exit` уже есть) и сторож вмешивался только при аварии.

    Проверка: остановить контейнер `docker kill` (не `stop`) и убедиться по логу, что сторож выдал
    `pca9685_probe off`.
  </action>
  <verify>

    <fails_when>скрипт не проходит синтаксис или не вызывает probe off</fails_when>
  </verify>
  <acceptance_criteria>

    - Обычный `docker stop` не даёт ложного срабатывания (SIGTERM успел, `ExecStopPost` не дублирует)
  </acceptance_criteria>
