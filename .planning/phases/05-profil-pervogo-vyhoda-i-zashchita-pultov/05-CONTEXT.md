# Фаза 05: профиль первого выхода и защита пультов — контекст

Требования: CAL-04, CAL-05, CAL-06, CAL-07, TEL-02, TEL-03, TEL-04, TEL-06, TEL-11.
Зависит от фаз 3 и 4 (защёлка драйвера, `FALLEN`, диагностика).

## Что уже есть на входе

- `robot.launch.py` собирает узлы из аргументов; профиля «пол» нет.
- `web_teleop` умеет E-STOP в обе стороны и `allow_calibration` по умолчанию **true**.
- `wsserver.py` (stdlib, без зависимостей) не проверяет `Origin`, не считает клиентов, не закрывает простаивающие.
- `cal_set` кладёт новые калибровки в драйвер через `SetParameters`; драйвер применяет их сразу, без ограничения ступеньки.
- `servos.yaml` читается из `dog_bringup/config` (каталог смонтирован в контейнер только для чтения); файла-надстройки нет, `.gitignore` про него не знает.
- `robot_setup --check` проверяет геометрию, но не симметрию зеркальных пар и не предел сервы в стойке.
- `docker-compose.yml`: `ROS_DOMAIN_ID=0`, диапазон обнаружения не задан.

## Решения

- **D-13 (владелец, 2026-10-29): клавиатура в профиле «пол» отказывается работать.** Отдельный процесс
  `keyboard_teleop` узнаёт профиль из латчированного топика, который публикует `locomotion`, и при
  `floor` не публикует команды, а пишет причину в лог. Проверять профиль в самом узле, а не полагаться
  на дисциплину запуска.
- **D-14 (владелец, 2026-10-29): калибровка заканчивается тегом `robot-calibrated-<дата>`.** Команда
  `git tag` печатается в конце работы `robot_setup`; значения при этом лежат в `servos.local.yaml`,
  который не отслеживается git (иначе `git pull` затирает калибровку). Тег ставится на коммит, где
  записаны откалиброванные значения, — так история «с какими параметрами ходили» не теряется.
- **D-15: один аргумент запуска `profile:=floor`.** Не отдельный launch-файл: профиль — это набор
  значений, которые подставляются в те же узлы, и один вход исключает расхождение между файлами.
  Профиль по умолчанию — `bench` (стол), чтобы стендовые прогоны и симуляция не менялись.
- **D-16: веб ставит E-STOP, но не снимает.** Нажать аварию — всегда можно (это безопасное действие);
  снять её можно только геймпадом (`button_release`). Это и есть формулировка TEL-02, и это же правило
  работает в обоих профилях.
- **D-17: ступенька при живой калибровке отклоняется, а не сглаживается.** Ограничение 10° для
  включённого канала проверяется в драйвере при `SetParameters`; отказ возвращает причину, инструмент
  калибровки видит её в `cal_set_result`. Плавный ход потребовал бы очереди изменений и таймера в
  драйвере — сложность ради редкой операции, а отклонение оператор видит сразу.
- **D-18: `ROS_DOMAIN_ID=42` и `ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST`.** Число выбрано, чтобы не
  совпасть ни с симулятором (домен 0), ни с тестами CI (домен 44).
