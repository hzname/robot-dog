# 07-04: аварийные проверки (SAF-18) — ОТКРЫТ, стенд

Проверки на роботе, пока он в люльке, каждая — с записью результата:

1. `kill -9` драйвера: таймаут команд 2.5 с → `bus fault latched`, выходы сняты.
2. `kill -STOP` драйвера: то же, но процесс жив — проверяется, что защёлка не зависит от
   завершения процесса.
3. Отключение питания Pi: сервы обесточены выключателем, повтор включения — драйвер стартует
   разоружённым.
4. Отсоединение SDA: шина молчит → драйвер не пишет мусор в сервы, ошибка видна.
5. Наклон в люльке: `fallen` и отказ `~/recover` до выравнивания.
6. E-STOP с падением ≈3 см: отпускание выходов, `fallen` не защёлкивается.

Кодовые защиты для этих проверок уже есть (фазы 3–5); здесь доказывается, что они работают на
железе.

## Что уже доказано без железа

`ros2_ws/src/dog_bringup/test/test_fault_drill.py` (мок-шина, три упражнения, ~46 с):

1. E-STOP туда и обратно — состояние уходит в `estop` и возвращается в `passive`;
2. смерть локомотива при стоящем роботе — драйвер держит 0.5 с, отпускает через 2.0 с и
   защёлкивает: `bus fault latched: no joint commands for 2.5 s … 1 command timeout(s)`, сервы
   обесточены, `~/release_fault` снимает;
3. отказ шины (`bus_fail_after`) — `fault latched (bus write failed 3 frames in a row)`,
   `~/arm` отказывает, снимает только `~/release_fault`.

Осталось на железе: физический `kill -9` (выходы гасит `servo-guard` на хосте), разрыв SDA,
питание, наклон в люльке.
