<objective>
Make the knee limits follow from the thigh x knee collision map computed from the owner's CAD (INPUTS sections 1-2) and
enforce them with numbers the existing driver already understands.

Purpose: the knee servo sits on the body and pulls the shin through a double parallelogram, so it sets the absolute shin
angle s = q1 + q2 (thigh + knee), not the knee alone. The admissible region is a rectangle in (q2, s). Writing the
coupling and a servo window equal to the free s range lets `jointToPulseUs` clamp the pair before a servo is driven
into a stop. This protects the servos (project Core Value) and keeps the Gazebo URDF limits in line.

Output: coupled calf rows and limits in `servos.yaml` / `robot.yaml`, a synchronised `urdf.py` default, contract and
driver tests, a guard in the `servo_pose` tool, the chart and a Russian doc section, and the open conflicts recorded in
`docs/REVIEW.md` and `deferred-items.md`.

Scope boundary (INPUTS section 3 and 5): geometry (`thigh`, `calf`, `hip_*`), hip limits, thigh limits, `lie_height` and
every C++ default stay as they are (geometry is plan 01-15). Untracked owner files (`01-MEASUREMENTS-RAW.md`,
`legacy/`, `robot_dog_ws/`, `.gsd/`) are not touched. No `git push`, no branch switch.

Tracer-first note: not applied. The coupling mechanism already exists in the driver and is covered by the `Coupling.*`
tests; this is a data change over four identical rows. Slicing it by leg would leave an asymmetric servo config between
commits, which is worse than one atomic config commit.

D-20 note: the phase decision D-20 (01-CONTEXT.md) says the knee rod rests on the thigh and `coupled_to` is not needed.
The owner's CAD (INPUTS section 2) shows the knee servo fixed on the body. The task input (INPUTS section 3.1) requires
`coupled_to`, so it is implemented and the contradiction is recorded in Task 3 for the owner to confirm. D-13 (one servo
speed number in three places) and D-15 (pinned ideal URDF) stay untouched.
</objective>

Facts established while planning (checked in the tree, not assumed):

- Driver semantics (`servo_driver.cpp`, `jointToPulseUs`): q is clamped to `[min_deg, max_deg]`; then
  `delta = direction * (q + coupling * parent - offset_deg)` is clamped to `+-range_deg/2` (direct drive) and `clamped`
  is set; pulse = `centerUs + servo_deg * usPerDeg`. `servo_driver_node` already reads `coupled_to` (string) and
  `coupling`, so no driver or node code change is needed.
- Window arithmetic (INPUTS section 3.1, updated by the orchestrator, see the note there): `offset_deg -32.5`,
  `range_deg 95.0` give s in `-32.5 +- 47.5 = [-80, +15]`. The window centre is NOT the mount pose: the project mount
  pose is thigh 45, knee -90, i.e. s = -45 at the centre pulse 1370 us of the servo (servos.yaml header: "all servos
  centred = half crouch"). To keep 1370 us = s -45 the pulse window is shifted by 12.5 deg * 9.4421 us/deg = 118.0 us:
  left legs (direction +1) `pulse_min_us 1039.5`, `pulse_max_us 1936.5` (middle 1488.0 us); right legs (direction -1)
  `pulse_min_us 803.5`, `pulse_max_us 1700.5` (middle 1252.0 us). `usPerDeg = (1936.5 - 1039.5) / 95 = 9.4421`
  (9.4444 for 520..2220 us on 180 deg, a 0.02 % difference). Check: left pulse(s=-45) = 1488.0 - 12.5 * 9.4421 = 1370.0,
  right pulse(s=-45) = 1252.0 + 12.5 * 9.4421 = 1370.0.
- Values to mirror in the C++ test (direction +1 / -1): q1=100, q2=-60 -> s=40 -> clamped to +47.5 deg of servo travel:
  pulse_max_us (1936.5) for direction +1, pulse_min_us (803.5) for direction -1. q1=57.5, q2=-90 -> s=-32.5 ->
  centerUs() (1488.0 / 1252.0). q1=45, q2=-90 -> s=-45 (mount pose) -> 1370.0 +- 0.1 us for both directions.
- Pose envelope from the JSON (`stance_envelope`), all inside q2 -140..-40 and s -80..+15: s ranges -68.6..-16.1.
- The ROS-free driver core builds locally: `g++ -std=c++17 -Wall -Wextra -Wpedantic -I ros2_ws/src/dog_hardware/include
  test_servo_driver.cpp servo_driver.cpp servo_bus.cpp -lgtest -lgtest_main -lpthread` compiled warning-free and passed
  17 tests at planning time. Only colcon/ROS is missing here.
- Baselines at planning time: `python3 -m pytest -q tools/robot_setup/test` 42 passed;
  `PYTHONPATH=ros2_ws/src/dog_description python3 -m pytest -q ros2_ws/src/dog_description/test` 21 passed (without
