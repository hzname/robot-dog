# Архитектура v2

## Узлы и топики

Все узлы работают в пространстве имён `/dog`.

```
 ┌───────────── пульты ─────────────┐
 │ gamepad_node ─joy─▶ joy_teleop   │
 │ keyboard_teleop (терминал / SSH)  │──cmd_vel, command, body_pose, estop──┐
 │ web_teleop (HTTP + WebSocket :8080)│                                      │
 └───────────────────────────────────┘                                      ▼
                                                                    ┌──────────────┐
                                                        state ◀─────│  locomotion  │ 50 Гц
                                                                    │режимы, рысь, │
                                                                    │ползание, IK  │
                                                                    └──────┬───────┘
                                                                  joint_commands (12 углов)
                             ┌────────── робот ──────────┐                 │
                             │ servo_driver ─I2C─▶ PCA9685│◀────────────────┤
                             │  калибровка, ограничение   │                 │
                             │  скорости, E-STOP          │                 │
                             └──────────┬─────────────────┘   ┌────────── симуляция ──────────┐
                                  joint_states                │ joint_command_bridge ─▶ Gazebo│
                                        ▼                     │ gz ─▶ joint_states, imu, odom │
                              robot_state_publisher ─▶ /tf    └───────────────────────────────┘

 Необязательные датчики (узел сам ищет чип на I2C и завершается, если его нет):
   imu_node (MPU6050) ── imu/data ──▶ locomotion (компенсация уклона, удержание курса)
   power_monitor (INA226/219) ── power, estop, command

 Восприятие рельефа (perception:=true; на роботе нужны драйверы датчиков):
   lidar_left/right/scan, gs2/scan, tof/<n>, imu/data, joint_states, odom
        ▼
   perception_node (C++) ── perception/hazards, ground_*, map ──▶ веб-пульт, запись
        ├── guard [max_vx, шаг ЛП, ПП, ЛЗ, ПЗ, походка, vy объезда] ──▶ locomotion:
        │         медленнее, выше шаг, ползание, стоп, шаг вбок в обход
        └── terrain/profile [x0, dx, n, высоты под левыми стопами, под правыми] ──▶ locomotion (опоры ползания)
   odom: на роботе — locomotion (счисление по походке и курсу IMU), в симуляции — Gazebo
```

## Пакеты (`ros2_ws/src`)

| Пакет | Язык | Что внутри |
|---|---|---|
| `dog_control` | C++ | `kinematics`, `gait` (рысь, высота шага по ногам), `crawl` (ползание на трёх опорах по профилю рельефа), `greet` (приветствие), `locomotion` (режимы, выбор походки, ограничения guard), `DeadReckoning` (одометрия счислением) — библиотека без зависимости от ROS; нода `locomotion_node` |
| `dog_hardware` | C++ | PCA9685 через Linux i2c-dev и mock-шина; ядро драйвера (калибровка, ограничение скорости, поочерёдное включение ног, E-STOP); нода `servo_driver_node`; `power_monitor_node` (INA226/INA219), `imu_node` (MPU6050, фильтр ориентации); утилита `pca9685_probe` |
| `dog_teleop` | C++ | `gamepad_node` (Linux joystick API), `joy_teleop_node`, `keyboard_teleop`; логика раскладок без зависимости от ROS |
| `dog_web` | Python | `web_teleop`: HTTP и WebSocket на стандартной библиотеке, страница с виртуальными стиками, клавиатурой и Gamepad API |
| `dog_description` | Python | генератор URDF из `robot.yaml` (xacro не нужен) |
| `dog_bringup` | launch | `robot.launch.py`, конфиги (`robot.yaml`, `servos.yaml`, `teleop*.yaml`), `calib_pose` |
| `dog_perception` | C++ (+ Python) | `perception_node` (C++): лидары «крестом», GS2 и VL53L1X — плоскость пола, карта высот, препятствия в коридорах стоп, реакция на них (guard) ([PERCEPTION.md](PERCEPTION.md)); тот же алгоритм на numpy (`dog_perception.core`) для проверок и видео |
| `dog_gazebo` | Python | `sim.launch.py`, миры (ровный, уклон, волны, камни, ступеньки, стенка, лестница, брус, блок), мост команд в Gazebo, `walk_check`, `terrain_sweep`, `perception_check` (в том числе `--greet`) |

Внешние зависимости — только `ros-base`: rclcpp, rclpy, стандартные сообщения, robot_state_publisher, launch. Для симуляции нужен ещё ros_gz.

## Режимы (`locomotion`)

```
PASSIVE ──stand──▶ STANDING_UP ──▶ STAND ◀──cmd_vel≠0 / =0──▶ WALK   (походка: рысь или ползание)
   ▲                                  │ │ lie                   │ lie (сначала дошагивает)
   │                          greet   │ ▼                       ▼
 estop (из любого)   GREETING ◀───────┘ LYING_DOWN ──▶ LYING ──stand──▶ STANDING_UP
                        └──▶ STAND (сама, через ~25 с)
```

- **Вставание и укладывание** идут по высоте корпуса с профилем минимального рывка (min-jerk). Стопы движутся строго вертикально, не скользя по полу.
- **Скорость** ограничивается по модулю и по ускорению (0.5 м/с², 2 рад/с²). При `cmd_vel` старше 0.5 с команда обнуляется.
- **Позу корпуса** (тангаж, крен, высота) можно менять в STAND и WALK, с ограничением скорости изменения.
- **Компенсация уклона.** Если приходит `imu/data`, стопы сдвигаются вниз по склону на h·tan(уклон), см. [TERRAIN.md](TERRAIN.md).
- **Удержание курса.** По гироскопу `imu/data` (ПИ-регулятор) контроллер доворачивает походку так, чтобы робот шёл по заданному курсу, см. [CONTROL.md](CONTROL.md).
- **Смена походки** (рысь ↔ ползание): её просит оператор (`crawl` / `trot`) или guard. Меняется только на месте: скорость обнуляется, и переключение происходит, когда походка остановилась и все стопы на одном уровне. Между двумя ступенями лестницы походка не меняется.
- **Приветствие** (`greet`) — только из STAND, стоя на месте, в рыси: сесть на задний край корпуса, передние лапы вверх, помахать, встать. См. [GAITS.md](GAITS.md).

## Походка

- **Рысь**: диагональные пары LF+RR и RF+LR. Период 0.55 с, доля опоры 0.65, так что есть фазы опоры на все четыре ноги (почему именно так — в [SIMULATION.md](SIMULATION.md)).
- **Опора.** Стопа «стоит» на земле: в координатах корпуса она каждый тик смещается против его скорости и поворачивается против угловой скорости.
- **Перенос.** Стопа идёт в точку `нейтраль + шаг/2`, где шаг = скорость стопы × время опоры (правило Рейберта), ограниченный 60 мм. По высоте — синусоида до 20 мм. По горизонтали стопа каждый тик проходит нужную долю оставшегося пути, поэтому траектория непрерывна при любых изменениях команды.
- **Старт и остановка.** Шаг начинается по первой ненулевой команде. Останавливается на приземлении, когда все стопы вернулись в нейтраль (±5 мм).
- **Ползание** — вторая походка: в воздухе всегда одна нога, корпус заранее смещается над треугольником трёх остальных, опоры выбираются по профилю рельефа. ~1 см/с. Для ступеней 25–70 мм, лестниц и высоких брусков: [GAITS.md](GAITS.md).

## Кинематика

Система координат по REP-103: x вперёд, y влево, z вверх. Система ноги находится на оси hip и параллельна корпусу.

- **Прямая:** `x = −L2·sin q1 − L3·sin(q1+q2)`. Точка (сторона·L1, z′) поворачивается вокруг X на угол q0.
- **Обратная:** q0 находится из плоскости y-z с учётом смещения L1, затем решается плоская задача для двух звеньев. Колено назад: q2 < 0. Недостижимые цели подтягиваются к границе рабочей зоны и помечаются.
- Тесты сверяют прямую и обратную кинематику на 1000+ точках, а также сверяют генерируемый URDF с формулами контроллера.
