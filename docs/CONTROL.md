# Управление: геймпад, клавиатура, веб

Все три способа публикуют одни и те же топики в пространстве имён `/dog`, поэтому их можно использовать одновременно. Действует последняя пришедшая команда.

| Топик | Тип | Что делает |
|---|---|---|
| `cmd_vel` | `geometry_msgs/Twist` | `linear.x` вперёд, `linear.y` влево [м/с], `angular.z` поворот против часовой [рад/с] |
| `command` | `std_msgs/String` | `stand` (встать), `lie` (лечь), `greet` (приветствие, [GAITS.md](GAITS.md)), `survey` (осмотр для карты), `crawl` / `trot` (походка оператора) |
| `body_pose` | `geometry_msgs/Vector3` | `y` — тангаж [рад], «+» опускает нос; `z` — сдвиг высоты [м] |
| `estop` | `std_msgs/Bool` | `true` — аварийная остановка (сервы обесточены), `false` — снять |
| `state` | `std_msgs/String` | состояние: `passive`, `standing_up`, `stand`, `walk`, `lying_down`, `lying`, `greeting`, `survey`, `estop` |

## Геймпад (USB или Bluetooth)

Геймпад подключается к Banana Pi. Нода `gamepad_node` читает `/dev/input/js0` через joystick API ядра Linux. Отдельный драйвер не нужен, отвалившийся по Bluetooth геймпад подхватывается снова автоматически. Нода `joy_teleop` переводит кнопки и стики в команды.

| Действие | Xbox (xpad) | PlayStation |
|---|---|---|
| **Держать, чтобы робот двигался** (deadman) | **LB** | **L1** |
| Вперёд / назад, шаг вбок | левый стик | левый стик |
| Поворот | правый стик влево/вправо | правый стик |
| Наклон корпуса (нос вверх/вниз) | правый стик вверх/вниз | правый стик |
| Полная скорость (без него половина) | RB | R1 |
| Встать / лечь | A / B | Cross / Circle |
| Приветствие (из стойки) | Y | Triangle |
| Высота корпуса | крестовина вверх/вниз | крестовина |
| **E-STOP** / снять E-STOP | **Back** / Start | **Share** / Options |

- Для PlayStation: `ros2 launch dog_bringup robot.launch.py gamepad_profile:=ps`.
- Если раскладка другая, посмотрите индексы через `ros2 topic echo /dog/joy` и поправьте `config/teleop.yaml`.
- Bluetooth на Armbian: `bluetoothctl` → `scan on` → `pair <MAC>` → `trust <MAC>` → `connect <MAC>`. После этого появится `/dev/input/js0`.

## Клавиатура (терминал, в том числе по SSH)

```bash
# в контейнере робота
docker compose exec robot ros2 run dog_teleop keyboard_teleop --ros-args -r __ns:=/dog
```

Терминал сообщает только о нажатиях, об отпусканиях — нет. Поэтому скорость набирается пошагово: каждое нажатие добавляет шаг, пробел останавливает.

| Клавиша | Действие |
|---|---|
| `w` / `↑`, `s` / `↓` | быстрее вперёд / назад (+0.03 м/с за нажатие) |
| `a` / `d` | шаг влево / вправо |
| `q` / `←`, `e` / `→` | поворот влево / вправо |
| `Пробел` / `k` | стоп |
| `1` / `2` | встать / лечь |
| `3` | приветствие: сесть, передние лапы вверх, помахать (из стойки, ~25 с) |
| `4` | осмотр: корпус качается вверх-вниз, затем влево-вправо на месте (из стойки, ~12 с) |
| `+` / `-` | высота корпуса |
| **`Esc` / `x`** | **E-STOP**; `r` — снять |
| `h` | справка; `Ctrl-C` — выход (отправляет стоп) |

## Веб-страница (телефон или ноутбук)

Откройте `http://<адрес-робота>:8080`.

- **Телефон:** два виртуальных стика (движение; поворот и наклон), кнопки «Встать», «Лечь», «Привет», «Осмотр», «Ползком» / «Рысью» и большая кнопка **E-STOP**. Плашка реакции показывает, что делает робот у препятствия: медленно, высокий шаг, ползание, стоп, объезд.
- **Ноутбук:** робот идёт, пока клавиша **зажата**. Браузер сообщает об отпускании клавиш, поэтому пошаговый режим здесь не нужен. `W A S D` / стрелки, `Q E` — поворот, `Shift` — полная скорость, `1` / `2` / `3` (встать, лечь, привет), `Esc` / `X` — E-STOP, `R` — снять.
- **Геймпад в браузере** (Gamepad API): та же раскладка, LB — deadman, Y — приветствие.
- Ползунки скорости и высоты.

Страница не требует интернета: всё отдаёт сама нода `web_teleop`, WebSocket реализован на стандартной библиотеке Python. Авторизации нет, поэтому запускайте её только в доверенной сети.

## Удержание курса по гироскопу

Рысь сама по себе уводит робота в сторону: ноги немного проскальзывают, и за полметра пути он поворачивается на 5–25°, каждый раз в случайную сторону. Если есть IMU (`/dog/imu/data`), `locomotion` держит курс сам:

- заданная скорость поворота сравнивается с измеренной гироскопом, а разница копится как ошибка курса;
- ПИ-регулятор добавляет к повороту походки поправку, не больше 0.3 рад/с. Интегральная часть убирает постоянный увод и работает только на прямой при малой ошибке, поэтому в развороте не перекручивает;
- поворот стиком сдвигает заданный курс вместе с командой, поэтому робот доворачивает ровно на столько, на сколько повернули стик. Без IMU разворот получается на 52–72 % из-за проскальзывания;
- стоя на месте, удержание выключено, и шум гироскопа не разворачивает робота. Если IMU замолчал дольше 0.2 с, удержание отключается.

Что показала симуляция: по 3 прогона на ровном полу и по 1–3 на уклоне 10°, волнах 20 мм и камнях 20 мм.

| | Без удержания | С удержанием |
|---|---|---|
| Увод курса на прямом манёвре, в среднем | 4–12° | 4° |
| То же, максимум | 11–34° | 6–9° |
| Разворот на месте, от заданного угла (ровный пол) | 52–72 % | 95–110 % |

Параметры лежат в `robot.yaml`, раздел `heading`: `hold`, `kp` = 2.5, `ki` = 1.0, `max_rate` = 0.3 рад/с, `max_error` = 0.5 рад. В симуляции выключается так: `sim.launch.py heading_hold:=false`.

**Гироскоп интегрируется по каждому отсчёту.** IMU шлёт 100 Гц, контроллер работает на 50 Гц. Раньше он брал последнюю скорость рыскания и умножал на свой шаг, так что половина отсчётов пропадала. Короткий рывок корпуса при проскальзывании лапы (~0,1 с) контроллер мог не увидеть вовсе. На лестнице это давало увод курса на 20–30°, хотя ошибка в контроллере держалась около нуля. Теперь каждый отсчёт интегрируется по меткам времени IMU (`addYawRate`), тест `HeadingHoldCountsEveryGyroSample`.

**В ползании свои коэффициенты** (`crawl_kp` 1.0, `crawl_ki` 0.2, `crawl_max_rate` 0.08 рад/с). Цикл ползания длинный (~9–10 с), и поворот делается только опорными лапами. Поправка 0,15 рад/с выносила шаг вбок на ±5 см и сужала опорный треугольник.

Удержание исправляет только поворот корпуса. Боковой снос (робот идёт прямо, но смещается вбок на несколько сантиметров) оно не убирает: для этого нужна оценка положения, например по лидару (см. [HEAD.md](HEAD.md)).

## Цепочка безопасности

| Что случилось | Что делает система |
|---|---|
| Отпустили deadman на геймпаде | `joy_teleop` сразу отправляет стоп |
| Геймпад отключился (Bluetooth) | через 0.5 с без данных `joy_teleop` отправляет стоп |
| Вкладка браузера закрыта, телефон заблокирован, пропал Wi-Fi | через 0.4 с без команд сервер отправляет стоп |
| Закрыли SSH / нажали Ctrl-C в клавиатурном пульте | отправляется стоп |
| Команды `cmd_vel` перестали приходить от любого источника | через 0.5 с `locomotion` останавливает шаг |
| `locomotion` упал | через 0.5 с драйвер держит последнюю позу |
| **E-STOP** (любой пульт) | драйвер **сразу обесточивает** все сервы, `locomotion` переходит в `passive`. Команды игнорируются, пока E-STOP не снимут и не отправят «Встать» |
| Остановился драйвер | выходы PCA9685 выключаются (`relax_on_exit`) |

> E-STOP обесточивает сервы, и робот **падает на корпус**. Чтобы просто остановиться, используйте «Стоп» (пробел или отпустить deadman), чтобы убрать робота — «Лечь».

Топик `estop` намеренно не сохраняет последнее сообщение (volatile). Если несколько пультов публикуют его с `transient_local`, узел, подключившийся позже, получит их последние значения в произвольном порядке и может, например, снять E-STOP. Вместо этого все узлы стартуют в безопасном состоянии: `passive`, сервы обесточены.
