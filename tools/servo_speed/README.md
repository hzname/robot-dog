# Анализ скорости серв по токовым следам (`servo_speed`)

Инструмент ищет скорость насыщения серв по токовым следам INA219 (CAL-17, D-08)
и выдаёт кандидата для `servo.max_speed`. Работает офлайн, без ROS: читает CSV
записи рампы (её снимет `dog_bench` на роботе, план 01-12), кросс-проверяет
результат по длительности хода и отдаёт JSON с флагами. Сначала метод
проверяется на синтетике, потом тем же кодом анализируется запись с робота.

## Установка

```
python3 -m pip install -r tools/servo_speed/requirements.txt
```

Нужен Python 3.8+ и numpy. matplotlib нужен только для необязательного
графика (`--plot`); сам анализ без него работает.

## Проверка без железа

Синтетический прогон, затем его анализ:

```
python3 tools/servo_speed/synth.py --v-max 6.0 --out /tmp/demo.csv
python3 tools/servo_speed/analyze.py --csv /tmp/demo.csv --out /tmp/result.json
```

`synth.py` пишет `/tmp/demo.csv` и `/tmp/demo.meta.json` и печатает пути;
`analyze.py` печатает строки вида `v_sat = 6 rad/s (ok)`, `agreement: yes` и
пишет JSON в `--out`. Для сервы на 6 рад/с ожидается `v_sat` 6 или 6.5.

## Формат входных данных

CSV с заголовком `t_s,stroke_id,direction,cmd_us,shunt_raw,bus_raw`:

| Колонка | Значение |
| --- | --- |
| `t_s` | секунды CLOCK_MONOTONIC |
| `stroke_id` | ход с 0 без пропусков; -1 вне ходов; строки от начала команды до конца выдержки после хода несут его номер |
| `direction` | +1 при росте `cmd_us` внутри хода и -1 при падении (выдержка входит в ход); вне ходов (`stroke_id` -1: APPROACH и REST рампы) допустимы -1, 0, +1 |
| `cmd_us` | выданный командный импульс, мкс |
| `shunt_raw` | знаковый регистр шунта, LSB 10 мкВ; ток = raw*10e-6/shunt_ohm |
| `bus_raw` | регистр шины как прочитан: напряжение в битах 15:3, LSB 4 мВ; пусто, если шина в этот такт не читалась |

Метаданные лежат рядом, в `<csv>.meta.json`:

| Поле | Значение |
| --- | --- |
| `shunt_ohm` | сопротивление шунта, Ом; обязательное, больше нуля |
| `us_per_deg` | перевод микросекунд импульса в угол, мкс/град; обязательное, больше нуля |
| `speeds_rad_s` | сетка скоростей (рад/с), строго возрастает, не короче четырёх; обязательное |
| `strokes_per_speed` | ходов на скорость, по 5 пар; обязательное, чётное и не меньше 4 |
| `amp_deg`, `center_us`, `channel` | амплитуда, центр и канал сервы |
| `hold_s`, `rest_s`, `ina_config`, `stop_reason` | тайминг и состояние запуска генератора |

`hold_s` не меньше 0.4 с: база тока берётся из конца выдержки предыдущего хода
(окно 0.15 с). Вне ходов поле `direction` может быть -1, 0, +1 (APPROACH и
REST пишут 0); внутри хода — только +1 или -1, иначе строка отклоняется с
номером.

## Как это работает и ключи результата

- след: сглаженный ток минус база (медиана окна 0.15 с перед первым
  изменением команды, то есть конец выдержки предыдущего хода);
- следы выравниваются по фронту роста тока, а не по команде: рассинхрон
  старта 0..20 мс не меняет `v_sat`;
- расстояние между средними следами соседних скоростей считается на окне
  0.6 с; порог «следы перестали различаться» —
  `eps = max(3*sigma_rep, 2 % от тока плато)` в относительных единицах
  (значение шунта сокращается);
- `v_sat_rad_s` — наименьшая скорость, после которой не меньше трёх подряд
  пар держатся ниже `eps`; сетка без насыщения даёт `not_saturated` и `null`,
  а не верхнюю скорость сетки;
- длительность хода даёт второй, независимый отсчёт
  `v_dur_plateau_rad_s`; допуск согласия 15 %; при расхождении берётся
  меньшее из двух (безопасная сторона) и ставится флаг
  `v_sat_v_dur_disagree`;
- коды выхода CLI: 0 — ok, 1 — not_saturated, 2 — ошибка входа.

Ключи JSON: `v_sat_rad_s`, `v_sat_status` (`ok` | `not_saturated`),
`v_dur_plateau_rad_s`, `v_dur_rad_s`, `agreement`, `servo_max_speed_rad_s`,
`flag`, `plateau_current_a`, `noise_floor`, `bus_v_mean`, `per_direction`
(`up`, `down`), `speeds_rad_s`, `distance_rel`, `eps_rel`, `strokes`.
Флаги: `not_saturated`, `v_sat_v_dur_disagree`, `insufficient_data`,
`saturated_at_first_speed`, `direction_mismatch`, `run_incomplete:<причина>`,
`many_strokes_rejected`.

## Как читать результат

- `ok` и `agreement: yes` — кандидат для `servo.max_speed`; число вносится в
  конфиг только после одобрения владельца (D-11);
- расхождение (`agreement: no`) — берётся меньшее из `v_sat_rad_s` и
  `v_dur_plateau_rad_s`, решает график `--plot`;
- `not_saturated` — серва быстрее сетки или следы не сошлись: выше 7 рад/с
  сетка 1.5..10 не даёт трёх пар, поэтому `v_dur_plateau_rad_s` читать как
  нижнюю оценку;
- `v_sat` бывает на ступень выше излома, `v_dur` ниже на несколько
  процентов, `us_per_deg` входит в оба;
- на быстрых сервах от 6 рад/с фаза 20-мс кадра ШИМ относительно начала хода
  разбрасывает длительность хода на 10-20 мс: в синтетике `v_sat` тогда
  выходит ниже излома с `v_sat_v_dur_disagree`, берётся меньшее, а решает
  график (план 01-14);
- флаги не блокируют вывод, но число без разбора не берётся.

## Условия замера (D-09)

- замер идёт на самом роботе, на подставке, ноги свободно висят;
- одна серва за раз (предпочтительно thigh — прямой привод, без тяги);
- без внешнего груза: нагрузка — вес собственной ноги; внешний груз не
  ставим;
- реальное напряжение шины; датчик INA219; `bus_v_mean` в отчёте — среднее
  по прочитанным регистрам шины;
- инструмент сам снимает выходы при токе выше порога и при любом
  завершении; рука владельца на питании.

## Запуск на роботе

Замер скорости серв на самом роботе (CAL-17, D-09). Сессию ведёт
`servo_speed_test run` из пакета `dog_bench`: рампа команд, предохранители,
CSV и `<csv>.meta.json` для `analyze.py`.

### Что подготовить

Лист замеров, часть 2 (`01-MEASUREMENT-SHEET.md`): мультиметр, маркировка
резистора шунта (R100 = 0.1 Ом или R010 = 0.01 Ом), адрес INA219 (0x41, 0x44
или 0x45), транспортир для перевода микросекунд в градусы (`--us-per-deg`).
Нога робота свободна (робот на подставке), рука на выключателе питания серв.

### Порядок

1. Остановить стек: `docker compose stop` — иначе `power_monitor_node`
   перезапишет конфигурацию INA219, а чужие каналы PCA9685 не дадут
   предстарту пройти.
2. Проверить чип: `pca9685_probe check` (инициализирует PCA9685 на 50 Гц) и
   `pca9685_probe off`; форма команд — в `docs/DEPLOYMENT.md`.
3. Проверить частоту опроса без серв: `selftest` (PWM не включается).
4. Посмотреть план: `dry-run` — ничего не трогает.
5. Запустить замер: `run` — спросит подтверждение `YES` (для скриптов есть
   `--yes`).
6. Вернуть стек: `docker compose up -d`.

Пример (серва `lf_thigh_joint`, канал 1; `--out` — в смонтированный каталог,
иначе файл пропадёт вместе с контейнером):

```
docker compose run --rm -v "$PWD/bench:/bench" robot \
  /ws/install/dog_bench/lib/dog_bench/servo_speed_test run \
  --ina-address 0x41 --shunt-ohm 0.1 --channel 1 --out /bench/servo_speed.csv
```

Без `ros2 run`: сигналы (Ctrl+C, остановка контейнера) должны доходить до
процесса напрямую.

### Коды выхода и `stop_reason`

| Код | `stop_reason` | Что значит |
| --- | --- | --- |
| 0 | `completed` | рампа прошла целиком |
| 1 | `overcurrent`, `saturation`, `implausible_shunt`, `ina_errors`, `pca_error`, `tick_overrun`, `timeout`, `signal`, `exception` | предохранитель, сигнал или отказ: выходы сняты |
| 2 | `invalid_config`, `refused_not_confirmed`, `refused_foreign_channel` | неверные аргументы или отказ до первого импульса |
| 3 | любая причина | выходы снять не удалось: питание серв выключить вручную |

### Что защищено, а что нет

Защищено: предохранители по току (порог и мгновенное насыщение шкалы), три
подряд ошибки INA, ошибка записи PCA9685, перебег тика, общий таймаут,
Ctrl+C / SIGTERM / SIGHUP / SIGQUIT (флаг, выходы снимаются за тик), падения
SIGSEGV / SIGABRT / SIGBUS / SIGFPE (одна запись `ALL_LED_OFF` в заранее
открытый дескриптор и код 3).

Не защищено: `SIGKILL`, потеря питания Banana Pi, зависание ядра — PCA9685
держит последний импульс. Вторая линия — рука владельца на выключателе
питания серв; после такого случая выключить питание и выполнить
`pca9685_probe off`.

### Анализ записи

```
python3 tools/servo_speed/analyze.py --csv bench/servo_speed.csv --plot
```

`--plot` кладёт рядом PNG: график «расстояние между следами» и «клюшку»
длительности. `not_saturated` при `v_dur_plateau_rad_s` от 7 рад/с означает
быструю серву (ворота D-11 проходят без правок уже от 6.35 рад/с), а не
сбой; отрицательный ток в отчёте значит, что шунт включён наоборот.

Константы INA219 в тексте называются по имени (`kIna219Fast320mv`,
`kIna219Fast80mv`); шестнадцатеричные значения регистров не цитируются.
